# Тестовое задание: цифровая визитка

> Смысл тестового задания в том, чтобы продемонстрировать навык использования всех перечисленных технологий.
> Время на выполнение не ограничено. **Упор на качество.**
> Убедительная просьба: либо отнеситесь к тестовому заданию серьёзно, либо не беритесь за него вовсе.

## Задача

Создайте свою цифровую визитку (backend-приложение), которая презентует вас как специалиста.

### Обязательные технологии

- Git
- TypeScript
- Node.js
- NestJS
- Prisma
- GraphQL
- Docker

Приложение должно предоставлять **Apollo Sandbox** (GraphQL Playground), через который можно получить информацию о вас, вашем опыте работы, навыках и проектах.

## Что должен содержать бэкенд

| #   | Раздел          | Поля                                                                                   |
| --- | --------------- | -------------------------------------------------------------------------------------- |
| 1   | **Профиль**     | имя; краткое описание; ссылки на GitHub / LinkedIn или другие профессиональные ресурсы |
| 2   | **Навыки**      | список навыков                                                                         |
| 3   | **Опыт работы** | компания; должность; период работы; достижения                                         |
| 4   | **Проекты**     | название; ссылка на проект / репозиторий                                               |

## Требования

- При запуске приложения база данных должна быть **автоматически подготовлена и заполнена** вашими данными.
- API должно позволять получить профиль и связанные с ним данные, например:

```graphql
query {
  profile {
    name
    description
    skills {
      name
    }
    experience {
      company
      position
    }
    projects {
      name
    }
  }
}
```

- Структуру GraphQL API, базы данных и архитектуру приложения выберите самостоятельно.
- Архитектурные решения нужно **обосновать в `README.md`**.
- Бизнес-логика, работа с данными и GraphQL API должны иметь разумное разделение ответственности.

## Что оценивается

В первую очередь оценивается **не количество написанного кода, а качество инженерных решений**.

Обратите внимание на:

1. Структуру приложения и разделение ответственности.
2. Работу GraphQL с вложенными данными для оптимизации запросов к базе данных.
3. Взаимодействие с базой данных.
4. Инициализацию и заполнение базы данных.
5. Читаемость и поддерживаемость кода.
6. Корректную работу приложения после запуска с нуля.
